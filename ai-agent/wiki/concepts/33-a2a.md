# A2A（Agent2Agent Protocol）

Google 发起、现由 Linux Foundation 托管的 **agent 之间**互操作协议。定位与 [[concepts/31-mcp]] 互补。

## 目标

让不同公司、不同框架、部署在不同服务器上的 agent **作为 agent（而非仅作为工具）**通信协作：

- 互相发现能力
- 协商交互模态（文本、表单、媒体）
- 安全地在长时任务上协作
- **不暴露内部状态、记忆或工具**（preserve opacity）

## 技术要点

| 项 | 内容 |
|---|---|
| 通信 | **JSON-RPC 2.0 over HTTP(S)** |
| 发现 | **Agent Card**（能力与连接信息清单） |
| 交互 | 同步请求/响应、流式 SSE、异步 push notification |
| 数据 | 文本、文件、结构化 JSON |
| 企业向 | 安全、认证、可观测性 |

## 与 MCP 的分工（记这一张表）

| | MCP | A2A |
|---|---|---|
| 连接 | agent ↔ 工具 / 数据 | agent ↔ agent |
| 对端 | 透明（schema 已知） | **不透明**（只知能力声明） |
| 发现 | `server/discover` + `*/list` | Agent Card |
| 典型场景 | 让 agent 会用 GitHub / 数据库 / Slack | 让 A 公司排班 agent 与 B 公司支付 agent 协作 |

可以同时用：一个 A2A 服务端 agent 内部照样用 MCP 连自己的工具。

## 什么时候**不需要**它

这是面试加分点：绝大多数所谓"多 agent 系统"其实是**同一进程内的 orchestrator-worker**（[[concepts/34-orchestrator-worker-multi-agent]]）或 **agents-as-tools**（[[concepts/35-manager-vs-decentralized]]），此时：

- 你完全掌握子 agent 的 prompt 与工具 → 不需要不透明性
- 通信是本地函数调用 → 不需要 HTTP 协议与 Agent Card
- 引入 A2A 只增加网络、鉴权、序列化开销

**需要它的条件**：跨组织、跨框架、跨部署边界，且不愿/不能暴露内部实现。

## 安全含义

跨 agent 边界会同时放大两类风险：

- **不可信输入**：对端 agent 返回的内容与工具输出同性质，可能携带注入指令（[[concepts/39-prompt-injection]]，"跨 agent 自我复制"是 OWASP 列出的传播行为之一）
- **权限扩散**：OWASP LLM03 明确要求"在委派或多 agent 工作流中**保留原始用户上下文与授权范围**"，不能只依赖调用方 agent 的身份权限（[[concepts/40-excessive-agency]]）
